# Sprint 10 UX 개선 — 2026-10-23

## 사용 흐름

1. **홈: 다음 할 일.** 진행 중인 케이스, 자료 연결 진척도, 최근 30일 기록 일수를 먼저 보여준다. 새 요청 준비와 거절 후 도움에는 설명을 붙인다. 음성 입력에는 질문과 예시 답변을 제공한다. 정기약·필요시 약·증상 버튼은 “버튼으로 기록하기” 안에서 펼친다. 중복된 최근 케이스 목록은 전체 목록으로 이동한다.
2. **기록: 누구의 어느 날인가.** Diego 같은 돌봄 대상의 기록을 기본 화면에서 선택한다. 달력의 청록색 약, 주황색 증상, 남색 환경 아이콘으로 날짜별 기록 종류를 구분한다. 날짜를 누르면 약·증상·환경을 아이콘 카드로 함께 본다. 원문은 카드를 눌러 확인한다. 기록 화면 간 순환 이동을 제거했다. 약 관리·사진 등록은 계정 본인의 약 관리 화면으로 연결한다. 원문은 보존하며 상세에서 사용자 동의 후 내 언어로 번역할 수 있다.
3. **자료 준비: 필요한 것만 먼저.** 음성 버튼을 위로 올리고 원문 설명·알림 설정·수동 기록을 접는다. “근거”는 “내 자료”, “치료 경과”는 “하루 기록”, “야간 각성”은 “밤에 잠에서 깸”으로 순화했다. 원본을 여는 버튼에 UUID를 노출하지 않는다.

## 원인과 수정

- 이전 기본 기록 탭은 계정 본인의 Sprint 9 테이블만 조회했다. Diego의 Sprint 10 patient key 기록이 별도 화면에 있어 기본 달력에는 나타나지 않았다. 기본 기록 화면을 대상별 이벤트로 연결했다.
- 환경 상세 화면은 GPS 실패 시 저장된 지역을 사용하기 전에 중단했다. 저장 지역을 허용하고 ZIP/city만 있으면 좌표를 해석한다.
- 실제 환경 API는 AQI를 `aqi_epa`로 반환하지만 클라이언트가 `aqi`/`us_aqi`만 읽었다. 실제 반환 필드를 추가했다.
- 실제 API 확인: 서버 응답 성공. AirNow unavailable, Open-Meteo/PurpleAir 등 응답 확인. pollen_upi는 null이어서 “꽃가루 수치가 정상 조회됐다”고 주장하지 않는다.

기존 합성 치료 기록 55건에 **환경 이력 30일**을 추가했다. `s10-ux-environment-v1` fixture를 사용하며 Diego patient key에 연결됐다. 교통 주변의 탁한 공기, 비 뒤의 습한 날, 이어진 꽃가루, 비교적 편안한 날씨 네 상황이다. 모두 SAMPLE이며 실제 지역 측정·실제 홍수·증상 원인으로 표현하지 않는다. 두 번 실행해도 같은 fixture ID에 기록하므로 중복되지 않는다.
