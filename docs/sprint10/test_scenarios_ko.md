# Sprint 10 기능 테스트 시나리오 — 한글

이 문서는 **기능 테스트 절차·기대값**이다. 촬영 순서·대사는 별도 [데모 영상 시나리오](demo_video_scenario_ko.md)를 따른다. 전체 테스트를 영상에서 모두 재현할 필요는 없다.

## 공통 준비

- 로그인: `diego@example.com`. 비밀번호는 제공된 값 또는 git 제외 `.env.demo`에서 확인한다.
- 계정 주인은 Rosa Martinez(38), 치료 대상은 아들 Diego Martinez(14)다. 로그인 이메일 변경은 인물 관계를 바꾸지 않는다.
- 기준일 **2026-10-22**, 뉴저지 시간대. 날짜가 바뀌면 30일 집계도 달라질 수 있다.
- A: `A - Before first request / SAMPLE` — 최초 요청 전. B: `B - Already denied / SAMPLE` — 앱 밖에서 이미 서류 부족으로 거절된 **대체 상황**. 두 케이스는 같은 Diego 기록을 재사용한다.
- 최신 APK 설치 → 로그인 → Spanish 언어 설정 → 대상 확인 → 기기에 문서 복사. AI 처리 동의와 마이크 권한은 실제 화면에서 받는다.
- 모든 문서는 합성이다. 처방·검사 수치는 진료 권고가 아니다. 표의 “수동 확인 필요”를 DB 검사 통과와 혼동하지 않는다.

## 핵심 입력 문서 세 가지

모든 PDF는 `output/pdf/sprint10-demo/`에 있고 각각 한 페이지다.

| 파일 | 입수 상황과 입력 방법 | 초기 DB 상태 |
|---|---|---|
| `04-lab-to-upload-live.pdf` | 환자 포털에서 받은 CBC 검사 PDF → 파일 선택 | **미등록**, TC-05에서 실제 업로드 |
| `05-lab-paper-for-camera.pdf` | 병원에서 받은 종이 CBC 결과 → 인쇄 → 기본 카메라로 촬영 → JPG 파일 선택 | **미등록**, TC-06 대체 입력 |
| `03-denial-notice.pdf` | 우편으로 받은 거절 통지서 → 인쇄·촬영 후 JPG 또는 PDF 선택 | B에 원본·사유·기한 등록됨 |

04/05는 **검체 DEMO-CBC-014, 검사일 2026-10-20의 같은 검사**다. 다른 사본을 두 번의 검사처럼 등록하지 않는다. 수치: WBC 7.0 x10^3/uL, hemoglobin 13.8 g/dL, platelets 280 x10^3/uL, absolute eosinophils 420 cells/uL. 참고범위도 합성 예시이며 임상 판단을 뜻하지 않는다.

보조 문서 `01-treatment-history.pdf`는 2026-07-04 시작 처방 이력(본문 작성일 10월 17일), `02-urgent-visit.pdf`는 2026-08-31 방문 기록이다. A/B에서 원본과 근거를 재사용하도록 DB에 준비했다.

**카메라 경로:** 현재 준비 화면의 자료 추가는 파일 선택이다. 종이는 **기본 카메라로 먼저 촬영한 후 사진 파일을 선택**한다. 준비 화면에 직접 카메라 버튼이 있다고 설명하지 않는다. 기존 거절문서 캡처 화면의 카메라 기능은 새 케이스 생성 경로이며 기존 B 수정과 다르다.

아래 항목은 **실기기 수동 확인 필요** 상태다. 서버 데이터 검사가 통과해도 이 표를 자동 통과로 처리하지 않는다.

|---|---|---|
| TC-01 | 로그인 → A/B 열기 | 같은 환자, 다른 시작 경로; 준비 화면 정상 열림 |
| TC-02 | A의 30일/12개월 전환 → 방문·처방 원본 열기 | 기간별 집계와 과거 방문 구분; 처방 이력은 복용 준수 증거가 아님 |

## 재촬영 및 검증 범위

TC-03/04는 Undo, TC-06/09/11은 저장 취소로 초기 상태를 보존한다. TC-05/07/10은 실제 기록/연결/출력을 바꾸므로 주요 촬영 마지막 테이크에서 실행한다. 검사 업로드 후 `node tool/sprint10_demo.mjs verify`의 “검사 미등록” 검사가 실패하는 것은 정상이며 이 도구는 **초기 상태 전용**이다.

자동 초기화/삭제는 하지 않는다. `refresh-documents`는 전용 계정의 세 원본만 갱신한다. 실제 기기의 사진 품질·ASR·AI 추출·공유·알림은 별도 실행 검증이 필요하며 APK 빌드 성공과 구분한다. 환경 데이터는 seed하지 않았으므로 실제 수집 성공 때만 보여준다.
