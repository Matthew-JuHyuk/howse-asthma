# Sprint 10 사용자 여정 중심 UX — 1.0.14

## 일관된 사용 흐름
앱의 목적은 보험 서류를 이해하고 필요한 기록·문서를 모아 의료진과 검토·전달할 자료를 준비하는 것이다. 매일의 짧은 기록은 그 준비에 쓰인다.

하단 메뉴는 **홈 · 케이스 · 기록하기(중앙 마이크) · 기록 · 설정**이다. 중앙 버튼은 화면 전환용 탭이 아니라 언제든 입력을 여는 행동이다. 버튼을 누른 것만으로 녹음하거나 저장하지 않는다.

1. 중앙 마이크 → 누구의 기록인지 확인한다. 케이스 안에서는 그 케이스의 환자로 고정하고, 전역에서는 본인·돌봄 대상을 선택한다.
2. 증상 / 약 사용 / 하루 상태를 고르면 해당 질문과 예시를 보여준다. 예시를 자동으로 기록 내용에 채우지 않는다.
3. **말하기 시작** 또는 **직접 입력할게요**를 선택한다. 말한 내용도 편집할 수 있다.
4. **내용 확인하기** → 원문에서 추출한 항목·날짜·대상을 확인한다. 다른 사람이나 불확실한 항목은 자동 선택하지 않는다.
5. 확인 후 저장한다. 케이스를 먼저 만들 필요가 없다. 기록은 환자에 귀속되고, 자료 연결은 별도 확인을 거친다.
6. 오류가 나면 입력을 남겨 재시도할 수 있다. 아직 서버에 동기화되지 않은 저장은 대기 상태로 알린다.

## 화면·메뉴별 역할
| 화면 | 우선 행동 | 정리 내용 |
|---|---|---|
| 홈 | 진행 중인 요청 계속 준비 | 자료 연결 현황과 기록 일수. 중복된 큰 녹음 버튼 제거. 기록 메뉴로 안내 |
| 케이스 목록 | 진행 중인 요청 열기 | 떠 있는 추가 버튼 제거. 상단 +에서 새 요청 준비/받은 서류 확인을 구분 |
| 케이스 상세 | 다음 할 일 수행 | 자료 모으기 또는 확인·전달을 우선. 중앙 마이크 유지. 편집·보관은 상단 더보기 |
| 자료 | 필요한 자료 확인·연결 | 종류별 아이콘과 상태. 상세 설명은 펼침. 내 기록 후보는 전체 화면에서 묶음 확인 |
| 기록 입력 | 짧게 말하거나 입력 | 대상 표시, 주제별 질문·예시, 음성/키보드, 고정 확인 버튼 |
| 입력 확인 | 내용과 대상 확인 후 저장 | 원문 유지. 개별 수정은 선택적으로 펼침. 내부 키·코드는 숨김 |
| 기록 목록 | 날짜별 변화 확인 | 복약·증상·환경 아이콘 달력. 중복 날짜 바로가기 제거. 날짜는 지역 형식으로 표시. 새 기록 저장 후 갱신 |
| 기록 상세 | 원문 이해 | 전체 화면에서 원문·번역 확인. 긴 팝업을 없앰 |
| 문서 촬영·추가 | 원본 넣기 | 기존 촬영·파일 선택을 유지. 용량 확인 및 원본 검토 후 저장. 긴 검토 내용은 전체 화면 |
| PDF·전달 | 검토하고 전달 | 실제 제출/승인을 의미하지 않도록 전달 보고와 구분. 이 화면의 집중 작업에는 추가 전역 메뉴를 억지로 넣지 않음 |
| 설정 | 언어·개인정보 관리 | 언어 우선. AI 동의와 서비스 관리는 펼침 그룹으로 정리. 계정 삭제는 별도 명시 |
| 약 관리·환경 상세 | 필요할 때 상세 확인 | 기록의 보조 도구로 유지. 약 사진 등록 경로 유지. 환경 수치와 합성 데모 이력을 혼동하지 않음 |
| 로그인·확인·파일 선택 | 작업 완료 후 원래 흐름 복귀 | 작성·확인 화면에서는 전역 메뉴를 숨겨 중복 입력과 내용 유실을 줄임 |

## 화면 규칙
- 기본 여백 20, 요소 간 간격 12~24. 제목·설명·보조 정보의 크기와 색을 구분한다.
- 하단 메뉴와 확인 버튼은 OS 안전 영역을 반영한다. 키보드가 있으면 확인 버튼이 키보드 위에 위치한다.
- 입력 중에는 마이크와 저장의 중복 실행을 막는다. 케이스에서도 반복 탭으로 입력 화면을 여러 개 열지 않는다.
- Android 음성 인식 초기화·중지·해제 실패는 오류로 처리해 직접 입력으로 이어갈 수 있도록 보강했다.

## 데이터·서버
`analyze-letter` 배포 완료. 케이스 없는 기록을 지원하되 로그인, 치료 처리 동의, 본인/등록된 돌봄 대상 검증을 유지한다. 타인과 등록되지 않은 대상의 요청은 차단한다. 기존 케이스 기반 요청도 호환된다.

`tool/check_record_entry.mjs` 실제 서버 점검: 타인 차단, 미등록 대상 차단, 본인 및 기존 자녀의 입력 검증 진입을 확인했다. 빈 입력을 사용해 유료 AI 호출이나 DB 쓰기를 하지 않았다. 임의 동의 생성이나 데모 데이터 덮어쓰기도 하지 않았다.

## 검증과 한계
- 중앙 버튼이 탭 선택을 바꾸지 않음, 열 때 자동 녹음하지 않음, 케이스 없이 입력 가능, 확인 전 미저장, 오류 시 내용 보존 검사 통과.
- 320dp / 글자 200% / 키보드 높이 240dp에서 확인 버튼 위치 검사: 영어·한국어·스페인어 통과.
- 기존 화면·자료 연결·환자 분리·출처·중복 저장 회귀 검사 유지. 2,000건 기록의 지연 렌더링과 하단 OS 영역 검사 통과.
- 실제 Flutter 화면을 390×844 크기로 렌더링해 중앙 메뉴와 안내형 입력 화면을 검토했다. 이미지는 기기 촬영본이 아니다.
- 실제 Galaxy 음성 인식, 3버튼/제스처 탐색 전환, 기존 종료 현상 재현은 연결 기기가 없어 아직 검증하지 못했다. 자동 검사 통과만으로 상용 출시 완료를 뜻하지 않는다.
- 새 안내 문구는 한국어·영어·스페인어를 제공한다. 일부 다른 언어는 영어 fallback이 남아 전체 번역 완료는 아니다.

## 설치 후 우선 확인
1. 홈·케이스·기록·설정에서 중앙 마이크를 누른다. 녹음이 자동 시작되지 않는지 확인한다.
2. Diego를 선택하고 질문 예시를 본다. 말하기 또는 직접 입력 후 내용을 확인해 저장한다.
3. 기록 화면에서 같은 대상·날짜의 저장 결과를 확인한다.
4. 케이스 → 자료 → 기존 기록 연결에서 묶음 확인 후 연결한다. 반복 열기·뒤로 가기를 시험한다.
5. 큰 글자와 키보드, Android 3버튼 탐색에서도 하단 버튼을 누를 수 있는지 확인한다.
