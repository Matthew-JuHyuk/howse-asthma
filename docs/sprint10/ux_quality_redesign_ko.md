# Sprint 10 UX 재구성 · 실기기 피드백 반영

## 앱의 목적
보험 서류를 이해하고, 필요한 기록과 문서를 모아 의료진과 검토·전달할 자료를 준비한다. 약 사용과 증상 기록은 이 목적을 지원한다. 앱이 보험 승인 여부를 판단하거나 보험사에 자동 제출하는 기능으로 표현하지 않는다.

## 화면 구조
- 홈: 앱의 목적 → 현재 케이스의 자료 준비 현황 → 계속 준비하기 → 하루 기록. 진행 중인 케이스가 있으면 다른 요청 시작은 펼침 메뉴로 이동한다.
- 케이스: 다음 할 일 하나를 우선 표시한다. 자료 연결 상태에 따라 자료 모으기 또는 확인·전달로 안내한다. 기록은 보조 카드에 배치한다.
- 내 자료: 문서 종류별 아이콘, 연결 상태, 기록 연결 버튼, 선택적 상세 설명 순서로 정리한다. 카드마다 같은 원문 버튼을 수십 개 나열하지 않는다.
- 이력 연결: 긴 다이얼로그를 제거하고 전체 화면으로 전환한다. 문서/증상 종류와 환자에 맞는 후보를 묶음으로 확인한다. 선택 변경을 열 때만 체크박스를 표시한다. 자동 후보 선택은 알려진 자료 분류에만 적용하고 실제 연결은 사용자의 최종 확인 후 저장한다. 다른 사람·취소 기록은 후보에서 제외한다.
- 기록·문서 확인: 긴 내용은 전체 화면에서 읽고, 확인 버튼은 하단 안전 영역 안에 배치한다. 내부 UUID, source ID, 영문 종류 코드 등 구현용 값은 표시하지 않는다.
- 최근 30일: 실제 기록 일수와 함께 표시한다. 30일을 보험사의 필수 충족 기준으로 표현하지 않는다.

## 안정화와 간격
- 공용 본문 SafeArea가 하단을 무시하던 설정을 수정했다. 시스템 버튼 영역은 별도 화면에서도 반영된다.
- 공용 버튼의 무한 가로 최소 폭을 유한 폭으로 바꿔 Wrap/Row 배치에서도 유효한 크기를 사용한다. 최소 높이 52, 내부 여백 20/16, 카드·버튼 사이 여백 12~24를 사용한다.
- 이력 연결 화면은 ListView.builder로 필요한 행만 생성한다. 기존 AlertDialog + SingleChildScrollView + 전체 Column 생성 방식을 제거했다.
- 연결 화면 중복 열기를 막고, 연결 화면을 연 상태에서 앱이 resumed될 때 케이스를 중복 로딩하지 않는다. 로딩 자체도 중복 실행을 막는다.
- 파일 용량을 읽기 전 확인하고 이미지 원본 미리보기의 디코딩 너비를 제한한다.

## 검증
- 전체 회귀 34개 통과. 실제 앱 테마를 적용해 360dp / 글자 200% 화면을 검사했다.
- 이력 2,000건에서 화면 밖의 모든 카드를 생성하지 않는지, 내부 ID가 노출되지 않는지, 개별 체크 없이 묶음 연결되는지, 48dp OS 영역과 하단 버튼이 겹치지 않는지 영어·한국어·스페인어로 검사했다.
- 렌더링 검사 1개 추가. 휴대폰 390×844 크기에서 케이스 개요·자료·연결 화면의 간격과 위계를 검토했다. 실제 기기 촬영본은 아니다.
- 시각 검토 후 수정한 자료 카드와 상단 메뉴를 포함한 관련 테스트 21개 재통과.
- 기존 처방 기록/검사 결과와 짧은 건강 일지가 혼동되지 않는 도메인 검사, 다른 환자 분리, 부정 표현, 취소, 중복 저장, 갱신 충돌 검사도 유지한다.

## 남은 실기기 확인
사용자는 최근 Android가 설치된 약 3년 전 Galaxy에서 케이스 상세의 이력 연결 중 멈춤·종료를 보고했다. 이 경로의 렌더링 부하와 중복 동작은 개선했지만 연결된 Android 기기가 없어 실제 ANR/crash 로그를 확보하지 못했다. 따라서 동일 기기 종료 현상이 해결됐다고 확정하지 않는다.

재확인 순서: 케이스 → 내 자료 → 기존 기록 연결 → 선택 변경 없이 연결 → 다시 열어 연결 유지 확인 → 뒤로 가기 → 반복. 제스처 탐색과 3버튼 탐색, 큰 글자, 키보드가 열린 확인 화면도 점검한다. 완전한 상용 출시 판정에는 동일 기기의 재현 검사와 전체 언어 검수가 추가로 필요하다.
