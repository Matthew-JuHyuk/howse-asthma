# CoverNote Sprint 10 — 두 경로 통합 설계·시연 버전 요구사항 및 작업계획
버전 1.5 | 결과 우선 시연·모국어 음성·앱 밖 기록 통합 | 작성 2026-10-22 America/New_York
대상: 다른 디바이스에서 기존 Flutter 앱을 수정할 Codex 및 프로젝트 책임자. 현재 세션에서는 문서만 수정하며 구현하지 않는다. 실행 프롬프트 파일명은 이전 링크 호환을 위해 Cursor_Sprint10_Prompt.txt를 유지한다.

## 1. 확정된 제품 방향
보험 편지 촬영 전용 앱에서 치료 재평가와 보험승인 자료 준비를 연결하는 앱으로 확장한다. 두 시작 경로가 하나의 환자 기록·근거 연결·문서 생성 기반을 공유한다.
- 케이스 1: 아직 승인 신청을 하지 않았다. 환자가 치료 변경을 의료진과 논의하고 병원이 최초 사전승인을 요청할 수 있도록 자료를 준비한다. 거절 레터를 요구하지 않는다.
- 케이스 2: 앱 밖에서 승인 요청을 했으나 거절 통지서를 받았다. 통지 사유와 이미 있는 자료를 대조하여 보완·재검토/이의신청 준비를 돕는다.
거절 뒤 다시 요청하는 것을 모두 ‘갱신 재승인’이라고 부르지 않는다. 기존 승인 만료에 따른 renewal은 별도 절차이며 이번 대표 경로가 아니다. 추가자료 요청(pending)은 거절과도 구분한다.
한 문장 목적: “CoverNote helps patients and caregivers turn treatment records and insurance requirements into an organized packet for their care team—before a request or after a denial.”
성공은 더 비싼 약 사용이나 보험 승인 확정이 아니다. 요구사항에 맞는 자료가 무엇이고 누가 가진 자료가 부족한지 명확해져 환자·보호자와 의료진이 다음 행동을 준비하는 것이다.
이번 명세는 사용자 화면·피드백 기반 설계이며 실제 저장소/DB/배포를 검사한 결과가 아니다. Codex가 구현 현황과 Sprint 8/9 회귀를 확인한다. 우선순위: 이번 두 경로 통합 요구 > 충돌하지 않는 Sprint 9/8 기능.

## 2. 제출 방식에 따른 개발 원칙
2026 공식 규정과 전국 toolkit 기준으로 영상·온라인 신청서가 핵심이다. 전국에서는 소스코드를 수집하지 않지만 지역 사무실이 요청할 수 있으며 심사위원은 앱/소스 접근을 요구할 수 있다. 공통 요건에 APK/IPA 업로드 의무는 확인되지 않았고, 실제 제출 폼의 지역 추가 항목은 접수 시 확인해야 한다.
따라서 결과물을 ‘설치 가능한 실제 앱의 합성 환자 시연 버전’으로 만든다. 화면 전환만 구현한 가짜 앱으로 바꾸지 않는다. Android release APK, commit, 설정/seed/reset, 네트워크 동작 증거를 보관한다. iOS/TestFlight는 이번 데모 완성의 선행 조건이 아니다.
모드 구분:
- Live: 새 입력과 실제 API/조회/문서 생성. 기존 합성 fixture 이름으로 정답 반환 금지.
- Demo: 합성 환자 데이터와 고정된 날짜로 재현, 동일 근거 연결/집계/문서 로직 사용. 실제 관측자료를 불러왔는지 합성 snapshot인지 구분.
- Replay/cache: 이전 합성 입력의 실제 분석 결과를 저장해 재생하는 촬영용 안정화 수단. 작은 표시와 설명에 ‘사전 분석된 예시’라고 명시하고 이를 새 실시간 AI 분석으로 주장하지 않는다. 미지 문서 분석은 별도 실제 검증.
2026 규정의 학생 기여/AI 사용 공개는 제출 검토 항목에 포함하되 이번 개발 구현을 기다리는 조건으로 삼지 않는다. 실제 Cursor/AI 기여를 학생 작성으로 허위 기재하지 않는다.

### 두 시나리오의 관계
동일 인물·임상 배경으로 A/B 두 시작 snapshot을 제공한다. A는 신청 전이며 거절이 없어야 하고, B는 앱 외부 신청 후 누락자료를 지적한 합성 거절이 있어야 한다. 이를 동시 진행하는 실제 두 환자/두 사건처럼 합산하지 않는다.
연속 시나리오도 지원: 준비 중 → 의료진에게 공유 → 병원 신청(사용자 보고) → 거절 통지 추가 → 같은 케이스에서 거절 대응으로 전환. 새로운 케이스 강제 복제 금지. 신청 시도/결정/이의신청을 별도 이벤트로 보존한다.

### 지역 환경의 역할
교통 관련 대기, 꽃가루, 침수 이후 습기, 캐나다 산불 연기 등은 NJ 지역 문제의 배경이다. 모든 요인이 같은 30일 동안 이 환자의 악화를 일으켰다고 구성하지 않는다.
- 사건별 날짜가 있는 장기 배경과 최근 30일 기록을 구분. 2023년 산불은 역사적 지역 사례로 설명 가능하지만 2026년 환자에게 그 관측값을 붙이지 않는다.
- 교통·홍수·꽃가루·연기는 관측/API, 사용자 생활 보고, 공공기관 경고, 합성값을 분리한다. 외부 습도를 실내 곰팡이로 표시하지 않는다.
- 혼잡통행료 때문에 특정 지역 매연이 증가했다는 주장은 측정 전후 비교 없이는 사실로 사용하지 않는다. Bergen County 공식 우려는 우려로만 인용한다.
- 환경자료는 치료 경과와 같은 시간축에 보이는 보조 맥락이며 검사/과거 치료 증명을 대체하지 않는다. 단순 동시 발생을 인과·보험승인 근거로 선언하지 않는다.

## 4. 화면 구조
하단 탭: 홈 / 내 케이스 / 치료 기록 / 설정. 별도 대기오염 앱 같은 메인 환경 탭은 만들지 않는다.
홈 첫 화면:
1. “치료 변경과 보험승인, 필요한 자료부터 함께 준비하세요.”
2. 주 CTA “새 약 보험승인 준비” / 부 CTA “거절 편지로 시작”. 두 경로가 스크롤 없이 보임.
3. “진행 중인 준비” 카드: 누가 무엇을 해야 하는지 다음 행동 하나.
4. 오늘의 짧은 기록. 케이스와 관련된 치료만, 임의 영양제 기록을 대표 시연 첫 화면에 노출하지 않음.
5. 시연 모드에서는 “합성 환자 예시” 배지와 A/B 시나리오 선택·초기화. 내부 demo 설정은 실제 사용자 화면과 구별.

케이스 공통 구조: 개요 / 준비할 근거 / 치료 경과 / 의료진에게 전달.
원본·전체 번역·인식오류 정정은 케이스2 ‘통지서 보기’ 안에서 접근. 정상 읽기 흐름의 핵심 화면을 긴 OCR 본문이 차지하지 않게 한다.
모든 화면에 언어 변경, safe area, 홈/목록 직접 이동, 자동 저장/복원. 기존 Sprint 9의 앱 이동 개선을 보존한다.

## 5. 필수 기능 요구사항(P0)
### S10-01 두 경로 진입과 케이스 타입
case_start_reason=new_request 또는 denied_request. 신청 전 경로에는 편지 업로드를 필수로 두지 않으며, 거절 경로에는 기존 거절 문서 입력을 제공한다. 문서 없이 정보만 입력한 경우 ‘통지서 미확인’ 표시, 원문에 근거한 사유처럼 보이지 않게 한다.

### S10-02 경로1: 최초 신청 자료 준비
최소 정보: 관련 질환/치료, 현재 약(확인된 라벨/처방/기존 등록), 환자·보호자 주요 걱정, 기록 기간. 요청할 새 약은 ‘아직 의사와 논의 전’ 가능.
의료진이 아직 약을 제안하지 않았으면 결과는 ‘진료 상담 준비 요약’. 약제별 자격 판정/자동 추천 금지. 제안 약과 적용 보험/정책이 확인됐을 때만 ‘최초 승인 자료 준비’에 정책 출처를 추가.
처음부터 30일 기록이나 검사파일을 요구하지 않는다. 이미 있는 진료·퇴원·검사 문서와 과거 치료 기간을 입력/업로드할 수 있다. “현재 기록만으로 요약 만들기” 허용, 데이터 기간/누락 공개.
산출물: 진료 목적과 주요 걱정 → 현재 치료/기록된 증상 → 응급진료 등 문서 근거 → 선택 환경 시간축 → 신청 준비 항목/누가 확인할지. 의료진이 작성/확인할 필드는 비워 두고 환자가 제공한 정보와 구분.
다음 행동: 의료진에게 검토 요청. 실제 신청은 병원이 하는 것으로 안내, 앱 공유를 보험 신청 접수로 기록하지 않는다.

### S10-03 경로2: 거절 사유별 대응
실제 촬영/PDF → 유형/원문 근거 추출 → 쉬운 사유와 다음 마감 → 거절 사유별 필요한 근거 → 기존 자료 자동 연결 후보 → 병원 요청사항 및 재검토 자료.
페르소나에서는 ‘커뮤니케이션 과정에서 자료가 누락됐다고 의심’할 수 있지만 앱은 의료진 과실을 확정하지 않는다. 확정 사실은 통지서에 쓰인 요청/누락과 원문 출처뿐.
거절, 추가자료 요청, 보험 자격/보장 제외, 갱신 통지, 청구 EOB를 구분. 이번 대표 경로는 최초 신청 거절 후 대응이며 사유에 따라 병원 보완 제출/재검토/이의신청 준비가 달라질 수 있다. 모든 거절을 동일 편지로 처리하지 않는다.
기한은 appeal/respond_by 등 type과 source를 보존하고 가장 가까운 필요한 행동의 기한을 개요에 표시. ‘항소기한 없음’ 때문에 별도 회신기한이 Unknown으로 사라지는 결함 수정.
산출물: 거절 사유 → 대응 자료/출처/누락/확인 주체 → 기존 신청에서 보완할 정보 → 의료진 검토 초안. 접수/승인 보장 없음.

### S10-04 근거 연결표 — 이번 차별화의 핵심
한 화면에서 요구사항과 환자 자료의 대응이 보이게 한다.
열: 준비할 내용 / 왜 필요한가 / 연결 자료·기간 / 출처 / 남은 일 / 확인 주체.
요구 출처는 notice / applicable_policy / care_team_request / optional_context로 구분. 한 출처의 내용으로 다른 출처를 사칭하지 않는다.
상태는 자료 없음 / 후보 있음 / 연결됨·미검토 / 의료진 확인 필요 / 임상자료로 확인됨(실제로 검토된 경우만). 자료 연결 건수는 승인확률·자격충족률이 아니다.
AI는 문서 사실을 추출하고 후보 관계/설명을 제안한다. 기록집계·기간·버전·정합성은 결정적 코드가 처리. 관계마다 실제 record ID 또는 page/quote 저장. AI가 만들어낸 치료 실패/검사/자료를 연결하지 못하게 검증.
근거가 부족한 부분이 완성된 것처럼 보이지 않게 한다. 실제 데이터로 최소 2개 항목은 ‘없음→연결 후보→연결됨’으로 바뀌는 시연을 구현.

### S10-05 기록이 연결되지 않는 결함 종료
같은 계정의 오늘 1건과 최근 30일 자료가 기록 화면/케이스 연결/PDF에서 일치해야 한다. 정상 empty state로 숨겨서 종료 금지.
RLS/user/profile/demo namespace, UTC/local_date, case creation 이전 필터, old schema adapter, pagination, sync_pending, cache를 조사. 본인 자료는 기간 안이면 신청/거절 전후로 자동 제외하지 않는다. 약 정의와 실제 사용 이벤트를 혼동하지 않는다.
오류/미동기화/기간 밖/진짜0건을 구분. 관계없는 약·비타민을 특정 천식 케이스 근거에 자동 포함하지 않는다. 연결 후보와 사용자 확인 단계를 유지.

### S10-06 치료 경과와 환경의 공통 시간축
정기약 사용, 필요 시 사용, 증상일/야간각성, 문서로 확인한 응급실 방문, 환경자료를 날짜별로 정렬. 최근 30일과 지난 12개월 중요한 사건을 구분.

## 5A. 추가 필수 요구사항 — 환자의 수고를 줄이고 즉시 가치를 돌려주는 UX
이 절은 S10-01~13을 유지하면서 확장한다. 충돌 시 최신 요건인 이 절을 우선한다. 제품 약속: “매일 긴 일지를 쓰는 대신, 짧게 남긴 기록과 이미 가진 문서로 다음 진료를 준비합니다.” 자동화는 입력·정리·재사용에 적용하며 환자가 하지 않은 행동을 생성하지 않는다.

### S10-14 P0 — 기록에 대한 즉각적인 보상
돈·포인트·연속출석보다 실용적 보상을 우선한다. 기록 직후 “오늘 기록이 진료 요약에 반영됐어요”와 실제 갱신 내용을 표시한다. 기록/문서가 실제 준비 항목에 연결되었을 때만 “준비 항목 1개에 자료가 연결됐어요”라고 한다. 승인 가능성·임상 적합성 상승으로 표현하지 않는다.
홈에는 환자가 얻은 결과(현재 요약 보기 / 병원에 물어볼 내용 / 다음 행동 1개)를 작은 카드로 보여준다. 빈 기록을 채우라는 압박 대신 현재 자료만으로 요약을 만들 수 있게 한다. 기록 전에도 기존 퇴원서·처방·진료 문서로 첫 결과를 제공한다. “30일을 기록해야 시작”하는 잠금 금지.
주간 요약은 유효 기록이 있을 때 앱 안에서 자동 갱신하고 알림은 별도 선택. “증상을 기록한 4일 / 기록한 날 5일”처럼 분모를 표시한다. 기록하지 않은 날은 무증상·미복약으로 추정하지 않는다. 정해진 기록일수로 준비완료 상태를 만들지 않는다.
비금전적 감사 문구는 가능하지만 streak 소실·건강점수 경쟁·구제약 사용량에 따른 보상·광고성 데이터 판매 유인·보장되지 않은 보험료 할인은 제외한다. 현금/쿠폰/보험 인센티브 계약은 Sprint10 범위 밖.

### S10-15 P0 — 홈에서 끝나는 최소 입력
앱이 이미 열려 있고 환자/치료가 선택된 상태: 홈의 약 이름·기본 기록 내용이 명시된 버튼 1탭으로 해당 사용 이벤트 저장, 별도 저장 버튼 없이 결과와 되돌리기 제공. 처방대로 전량 사용했다는 확인을 모호한 “오늘 완료” 버튼으로 대체하지 않는다. “사용했어요”가 저장할 내용이 무엇인지 버튼 옆에 설명한다. 미정 용량은 사용 사실만 기록하며 처방용량을 실제 사용량으로 채우지 않는다.
약 카드의 정기약과 필요 시 구제약을 구분. 구제약은 “사용 기록”→횟수/퍼프 선택→선택 즉시 저장, 홈에서 2탭 이내. 처방 권장량을 제안하는 기능이 아니다. 다약제는 이름·사진/아이콘으로 식별하고 모든 약을 한꺼번에 사용한 것으로 기록하지 않는다.
증상은 홈에서 “증상 남기기”→쉬운 선택 1개(예: 기침/쌕쌕거림/밤에 깸)로 최소 이벤트 저장, 2탭 이내. 자세한 내용은 선택. 해당 시점에 선택한 증상만 저장하고 나머지는 없음으로 채우지 않는다. 증상 없음도 사용자가 명시적으로 선택한 경우만 기록한다.
동일 복약 회차 버튼 중복 탭은 중복 저장 방지; 실제 추가 구제약 사용은 별도 이벤트로 허용. 오류 수정/되돌리기는 복약 권장 취소가 아닌 기록 정정임을 명확히. 로그인 만료·기기 잠금·초기 설정의 탭 수는 별도 측정하여 숨기지 않는다.

### S10-16 P0 — 점진적 설정과 쉬운 이해
언어와 본인/보호자·대상 환자 확인 후 최소 흐름 시작. 위치·알림·문서 AI 동의를 한꺼번에 요구하지 않고 필요한 시점에 이유를 한 문장으로 안내. 거절하면 대체 흐름(동네 선택/알림 없이 사용/수동 입력)이 동작한다.
큰 주요 버튼, 아이콘+텍스트, 쉬운 표현, 화면당 주요 행동 1개. 색상만으로 상태 전달 금지. 한국어/영어/스페인어 주요 여정에서 글자 확대 200%, 스크린리더 이름/상태, Android 최소 48dp 터치영역을 검증한다. 화면을 긴 고지문으로 채우지 말고 필수 안내는 짧게, 상세는 펼침.
한 번 확인한 약·보험·언어·환자·문서 정보는 두 경로와 PDF에서 재사용하며 재입력을 요구하지 않는다. 보호자 기록은 대상 환자와 작성자를 보존. 두 번째 보호자 공유는 기존 권한 모델로 실제 검증되는 경우만 제공하고 신규 가족계정 협업은 후순위.

### S10-17 P0 — 자동 수집과 자동화의 정확한 경계
각 기록에 환자, 이벤트 발생 시각, 입력 시각, 시간대, 입력 경로, 수정 이력/출처를 자동 부착. 위치는 선택한 동네 또는 명시적으로 허용한 현재 위치를 쓰며 약 사용과 무관한 상시 GPS 추적은 하지 않는다.
약 라벨/퇴원서/처방 사진에서 AI가 후보를 추출해 확인 카드 제공. 고위험 값(약명·용량·환자·날짜)은 원문과 확인 가능해야 하며 불확실하면 비워 둔다. 한 번 확인한 값은 재사용. 문서 날짜가 없거나 충돌하면 사용자 확인, 업로드 시각으로 원래 사건 시각을 대체 금지.
환경은 서버가 선택 지역의 시각이 있는 관측값을 조회·캐시하고 기록 시 가까운 유효 관측과 연결. 지역·출처·오염물질·관측시각·거리/해상도·자료 품질을 보존. 현재 날씨로 과거 증상을 메우지 않는다. 결측/오래된 자료/조회 실패를 정상값과 구분. 조회 완료가 복약·증상 저장을 막지 않도록 비동기 연결.
공통 기록 원본 1개를 여러 케이스/문서가 참조하며 집계·요약 초안을 자동 갱신. 이미 생성/전달한 PDF는 덮어쓰지 않고 새 revision 필요 표시. 자동 연결은 근거 후보이고 임상 검증이나 승인 요건 충족 판정이 아니다.
스마트 흡입기·웨어러블·약국/EHR/FHIR 연결·NFC는 이번 필수 구현에서 제외한다. 음성과 앱 밖 기록은 S10-21~22에서 P0로 승격한다. 전화기만으로 복약/천식 증상을 자동 측정했다고 표시하지 않는다.

### S10-18 P0 — 연결 없이도 기록, 필요한 만큼만 독려
오프라인에서도 짧은 기록은 기기에 저장하고 동기화 대기 표시. 재전송은 idempotency로 중복 방지. 실패 시 입력을 잃지 않고 재시도, 다른 환자/계정으로 대기 기록이 넘어가지 않게 한다.
앱 내 “오늘 10초 확인” 카드는 제공하되 실제 소요시간 검증 전 10초가 보장된다고 광고하지 않는다. 알림은 선택, 사용자가 시간/빈도·일시중지·해제를 정한다. 기본 상한 하루 1회, 기록 완료하면 일반 기록 알림 생략, 무응답 누적에 따라 더 자주 보내지 않는다. 잠금화면에는 약명·진단 등 민감한 정보 노출 금지.
최소 알림 기능: 탭하면 해당 환자의 간단 기록 화면으로 바로 이동하여 메뉴 탐색 생략. 앱 밖 직접 기록은 S10-22의 P0에 따른다. deep link만 구현한 것은 앱 밖 직접 저장 완료로 계산하지 않는다. 과도한 푸시·30분 반복 알림 제외.
현재 호흡이 힘든 순간에 상세 기록을 요구하지 않는다. 기존 긴급 도움 경로를 가까이 두고 기록/서류보다 적절한 도움을 먼저 받게 한다. 구체 진료 지침은 검증된 기존 안내를 유지, AI 응급 판정 새로 생성 금지.

### S10-19 P0 — 환경 노출·증상·의료 이용 부담을 보여주는 사실 요약
환자 부담 카드는 증상 기록일/관측일, 야간 사건, 구제약 사용, ED/입원/추가 진료를 원자료로 계산. 처방 변경과 환자 보고 실제 사용량은 구분하고 단위가 다른 약 사용량을 합산하지 않는다. 이전/최근 기간 비교에는 기간 길이·기록한 날 수·결측을 함께 표시. 적은 기록의 비율을 일반 위험도로 표현하지 않는다.
선택 노출 기록: 매연 냄새/트럭 많은 곳에 머묾/침수 후 실내 습기 등 한 번 선택으로 사건 저장. 사용자 보고와 실제 교통량·지역 관측값은 다른 출처로 유지. AQI만으로 디젤 매연이나 특정 트럭 기여도를 판정 금지. NO2/black carbon/교통량 자료는 실제 확보·품질 검증된 것만 표시.
응급실/입원은 환자 보고·업로드 문서 확인을 구분. 비용은 확인 자료가 있는 경우만 청구액/실제 보험 지급액/본인 부담액/통화/날짜로 구분. 자료 없는 달러 금액과 절감 예상치를 만들지 않는다. 비용 자료 없이도 의료 이용 횟수는 표시 가능. 비용 필드 입력은 일상 기록의 선행 조건이 아니다.
개인 PDF에 간단한 환자 부담 및 출처 요약을 포함하고, 환경은 보조 맥락으로 설명. 정책 요구 검사·과거 치료 증명을 대신하지 않는다. “함께 기록된 사건”이지 통행료/매연이 악화·응급실 방문을 일으켰다는 판정이 아니다.

### S10-20 P1 — 지역 활용 예시는 합성 집계로 제한
별도 개인정보 동의·집계 기준·소수집단 보호·철회/삭제 전파를 설계하기 전 개인 건강·위치 자료를 의원실/보험사에 전송하지 않는다. P1 시연 화면은 합성 집계임을 표시하고 실환자 지역 피해 통계로 주장하지 않는다. 실제 옵트인 수집·외부 데이터 제공·실시간 지도는 이번 P0 범위 밖.
모집된 참여자는 지역 인구를 대표하지 않는다. 표시 시 참여자 수·기록한 날·자료 출처를 함께 제시하고 효과/피해 규모의 인구 추정으로 확대하지 않는다. 개인 치료 준비가 주 흐름이며 집계 기능으로 핵심을 지연하지 않는다.

### 설계 우선순위와 실용성 검증
P0: 두 경로 유지 + S10-14~19 + S10-21~23. 앱 밖 기록은 홈 위젯/알림 직접 액션 중 하나를 P0로 구현하고 다른 하나는 P1. P1: 추가 앱 밖 경로/합성 지역 집계. P2: 웨어러블/EHR/NFC/금전 보상/기침·흡입기 음향 감지/잔량 카운터 인식. P1/P2를 완료율 산정의 P0와 섞지 않는다. 일정은 실제 저장소 감사 후 재산정하며 기존 6.5~12시간은 추가 범위 이전의 계획값으로 더 이상 전체 확약이 아니다.
정량 목표는 구현 목표이지 입증 효과가 아니다. home-ready 기준 정기약 1탭, 구제약/최소증상 각2탭, 자유 텍스트 0개로 기본 기록 완료. 앱 종료/잠금/초기 가입 시간은 별도 측정. 대표 보호자 과제 테스트 3~5명(가능하면 언어/IT장벽 반영)으로 첫 기록·다음 행동 이해·재방문 결과 찾기·오입력을 관찰하고 실제 결과/표본을 보고한다. 미실시이면 미검증으로 표시.
반복 사용 유인은 “오늘 남긴 정보가 내 다음 진료와 준비 자료를 바꾼다”로 통일. 지속 이용률/보험승인률/의료비 절감을 테스트 없이 주장하지 않는다.

'"## 5C. 최신 범위 확정 — 음성과 결과 중심 데모 (v1.3)
이 절은 이전의 음성·위젯 후순위 지정을 대체한다. 목표는 새로운 메뉴를 늘리는 것이 아니라 “짧은 환자 설명→검토 가능한 근거→다음 행동” 하나의 여정을 완성하는 것이다. 병명부터 시작하는 시연을 피하되 실제 앱의 천식 사례와 의료적 한계를 감추지 않는다.

### S10-21 P0 — 모국어 음성에서 기록으로
홈에 “말로 남기기”. 녹음 시작→짧은 말→자동 종료 또는 중지→확인 카드→한 번 확인으로 이벤트 저장. 환자가 정기적으로 녹음해야만 앱을 쓸 수 있게 만들지 않고 기존 버튼 입력도 유지한다.
파이프라인: 음성인식→선택 언어 원문 표시→구조화 후보→대상/시점/약/수량 등 확인→원자적 저장→타임라인/연결 후보/요약 갱신. 영어/스페인어/한국어 대표 fixture를 검증한다. 한 발화에서 여러 이벤트를 만들면 개별 event ID와 동일 source ID를 보존하고 중복 생성을 막는다.
예시 “어젯밤 아이가 기침 때문에 두 번 깼어요. 파란 흡입기를 썼는데 몇 번인지는 기억나지 않아요.”: 야간각성2회·기침·약 사용 보고 후보, 약명 미확인/사용량 모름. 색으로 약을 확정하지 않는다. “기침을 두 번”과 “두 번 깸”을 구분. 다른 가족 이야기·부정·과거·정정 표현·상대 날짜에 대한 테스트 포함. 약 사용량/처방변경을 추측 금지.
원문과 구조화 정보의 대응을 보존하고 수정 가능. 음성인식 후보를 자동 확정하지 않는다. 명확한 필드는 빠른 확인, 모호한 필드는 선택적 질문만; 불명확하면 모름으로 저장하고 전체 기록을 막지 않는다. 기록 확인과 별개로 임상적으로 검증됐다는 라벨 금지.
짧은 사용자 시작 녹음만, 마이크 권한 거절·미지원·인식실패 시 버튼 입력. 기기 내 인식 지원과 언어 지원은 실제 기기에서 탐지, 온디바이스가 아닌 경우 그렇게 주장하지 않는다. 서버 음성 처리 시 전송 고지·동의·보관정책 적용. 원음 기본 미보관, 처리용 일시 파일/서버 수명 최소화; 원문 텍스트·구조화 출처는 계정 정책에 따라 저장/삭제. 장시간 상시 녹음 없음. 오프라인 텍스트/버튼 기능은 유지하고 지원되지 않는 오프라인 음성은 실패를 명시.
의료진용 영어 요약은 확인된 원문의 의미를 보존, 불확실성/약명/용량 누락을 그대로 표시. 시연의 발화는 실제 새 입력으로 처리하며 미리 정해둔 결과를 문장 키워드로 반환하지 않는다.

### S10-22 P0 — 앱을 찾아 열지 않는 기록
Android 홈 위젯 또는 알림 직접 액션 중 실제 기기에서 안정적인 하나를 선택해 P0 구현. 감사 문서에 선택 이유/지원 OS/API/기기잠금·사용자 식별·백그라운드 제한을 기록. 다른 경로는 P1.
대상과 이벤트가 사전 설정·명시된 경우 앱 화면 진입 없이 1탭 저장을 목표로 한다. 민감정보 표시를 최소화하고 다중 환자/계정 전환·로그아웃·잠금에서는 확인/인증이 필요할 수 있음을 정직하게 보고. 전체 약 사용/완전 복약으로 추정 금지. 피드백·되돌리기·중복방지·오프라인 큐·기존 기록 집계 일치를 검증. 단순 앱 실행 shortcut과 실제 직접 기록을 혼동하지 않는다.
확장이 개발 시간을 쓰면 두 경로/음성/근거 연결을 먼저 완성하되 미구현 P0를 완료로 표시하지 않는다. widget와 알림 둘 다 만들겠다고 범위를 무조건 늘리지 않는다.

### S10-23 P0 — 결과부터 보여줄 수 있는 검토 요약
작동하는 실제 결과 화면은 목적/핵심 부담/연결된 근거/남은 일/다음 담당자를 짧게 표시하고 각 출처로 이동 가능. 영상 첫 장면에 작은 글씨 PDF 전체 대신 이 화면을 쓰며, 종이 문서는 후반 상세 확인용이다. 결과 화면은 일반 사용자에게도 의미 있는 UI이며 영상만을 위한 허위 진행상태를 만들지 않는다.
개요에 “의료진 검토용”을 표시. 근거가 일부 연결돼도 임상 준비/승인 완료로 표현하지 않는다. 첫 결과는 기록일수가 아니라 현재 있는 자료에서 만들며 미확보 자료를 명시한다. 동일 confirmed event가 음성 확인/타임라인/근거표/PDF에서 추적 가능해야 한다.
시연 첫 요약은 합성 seed의 실제 생성 결과이다. “이 결과가 어떻게 만들어지는지”로 전환해 입력을 실제 시연한다. 첫 결과와 재연한 과정은 동일 fixture/revision 기준으로 맞추되 새 기록을 재입력한 복제는 reset된 snapshot에서 진행한다. 화면전환으로 데이터 변경·실시간 처리 시간을 속이지 않는다.

“환자의 경험을 의료진이 검토할 자료로 연결한다.” 영어 제품 메시지: “Turn a patient's experience into a clear next step for care.” 보험승인은 두 사용 상황이며 의료진 검토를 위한 준비가 공통 목표.
차별성은 혁신/최초를 반복하는 문구가 아니라 ①모국어 발화의 실제 구조화 ②같은 날짜 환경 자동연결 ③동일 자료의 요구사항별 재사용 ④정리된 다음 행동이라는 화면 변화로 보여준다. 경쟁 앱에 없는 기능/독창성/효과는 비교검증 전 단정하지 않는다.
NJ는 대표 페르소나의 실제 문제 맥락으로 설명: 언어·의료접근 부담과 교통 관련 대기/꽃가루/침수 후 습기/연기 같은 지역 환경의 날짜가 있는 자료를 함께 검토할 수 있도록 설계했다는 것. 이 요인 전부가 한 환자의 같은 기간에 발생했다는 설정 금지. 지역 유효성은 아직 임상/현장 효과로 입증되지 않았으므로 designed for/목표로 표현한다.
소송·통행료·오염 원인 논쟁·통계 나열·기침 센서·지역 집계·보상 포인트·범용 웰니스 화면을 메인 영상에 추가하지 않는다. 상세 배경/확인 출처는 제출 답변·부록으로. 합성 표시와 불확실성은 설명을 길게 하지 않고 해당 화면에서 읽을 수 있게 한다.

## 6. 환자 규모와 발표 근거 작업
현재 직접 확인한 동일 연도 기준선:
- CDC 2023 NJ 소아(<18) 현재 천식: 153,048명, 7.8%. NSCH 조사 추정치.
- CDC 2023 NJ 성인(18+) 현재 천식: 627,531명, 8.6%. BRFSS 조사 추정치.
- 두 연령대 조사 추정치의 단순 합은 약 780,579명(약78만). 공식 단일 전수 집계라고 표현하지 않는다.
위 숫자는 이번 페르소나 전체 조건(경제·언어·치료 어려움·환경·승인 거절)을 동시에 충족하는 사람 수가 아니다.

정량 후속 작업의 두 모집단:
A. NJ 천식 환자 중 치료 재평가/최초 승인 준비가 필요한 환자·보호자.
B. A와 겹칠 수 있는 승인 거절 후 대응 준비 환자·보호자. A+B를 신규 고유 환자 수로 단순 합산하지 않는다. 환자 수와 승인 요청/거절/ED 방문 건수도 구별.
조사 순서: NJ/CDC 천식 → 소아 Medicaid/FamilyCare 분포 → 보호자의 언어 지원 필요(환자 본인의 언어와 구별) → 치료 조절/급성 이용/치료변경 지표 → 약제별 PA/거절 정보. 공동분포 자료를 우선, 없으면 조건부 시나리오 추정으로 표시.
환경 4종 노출을 전부 AND로 걸어 인구를 추정하지 않는다. 다양한 환경 배경은 대표 인물의 생활 맥락이며 제품 사용 자격 요건이 아니다. 인종/외국출생률을 LEP와 동일하게 취급하지 않는다. ED 방문 건수로 야간 방문 환자/향후 재방문 확률을 계산하지 않는다.
모든 계수는 근거 표에 출처/연도/지리/분모/연령/불확실성을 기록. 교집합 근거가 없으면 단일 숫자를 만들지 말고 ‘미확정’ 또는 가정별 범위를 제시. 임의 비율을 곱한 값을 공공 통계처럼 발표하지 않는다.
완료 산출물: Population_Evidence.md(확인 통계와 계산식·가정 구분), Citation_Cards.md(화면/영상에서 그대로 인용할 2~3개 숫자), Persona_Data_Dictionary.md(페르소나는 합성이라는 명시).
오늘의 개발은 이 좁은 교집합 숫자 확정을 기다리지 않는다. 발표의 기본 분모는 검증된 ‘NJ 약15.3만 소아 천식 환자’로 시작 가능하며 그 전체가 본 앱의 검증된 고객이라고 부르지 않는다.

## 9. 제출·시연 준비
필수 준비(실제 폼에서 최종 확인): 참가자/팀 자격·연락처·보호자 정보, 온라인 신청서, 앱명·목적·대상·개발동기·도구/언어·기술적 문제 해결·배운 점 등 답변, 1~3분 공개 YouTube/Vimeo 시연 영상, AI/외부 도구·실제 기여 공개. 2.0이라면 새로운 기여를 구분.
보관/요청 대비: 고정 release APK, source commit/archive(비밀 제외), demo test account/실행·reset 설명, 증거 자료와 출처 목록, 실제 네트워크/파싱/근거 연결 검증 기록. 공개 비밀번호나 실환자정보는 영상에 넣지 않는다.
옵션 보조자료: 페르소나 카드, 전후 비교, PDF 샘플, 아키텍처 그림. 폼이 요구하지 않는 파일을 필수 제출물로 단정하지 않는다. 국회의원 사무실에 연락/영상 공개/신청서 제출은 사용자의 명시적 요청 후 진행.

2분50초 결과 우선 storyboard (확정 방향, 상세는 CoverNote_Sprint10_Demo_Outline.md):
0:00~0:06 실제 합성 결과 화면 확대: 출처 있는 근거/남은 일/다음 담당자. 이름·앱명 자막. “Your experience should not get lost in paperwork.”
0:06~0:20 NJ 가족의 치료·승인 준비라는 목적과 대상, 모국어 설명→지역 맥락→의료진 검토라는 작동 방식. 병명/통계/소송으로 시작하지 않는다.
0:20~0:45 보호자가 실제 스페인어 발화→확인 카드→저장. 번역만이 아니라 시점/증상/약 불확실성을 구조화하는 장면.
0:45~1:05 기존 처방/응급실 문서와 환경을 같은 날짜에 연결. 환경을 폰이 직접 측정하거나 원인 입증했다고 표시하지 않는다. 앱 밖 직접 기록은 최대3초 삽입, 주 여정 분기 금지.
1:05~1:30 케이스1: 편지 없이 최초 신청/상담 준비, 실제 자료와 남은 병원자료를 보여줌.
1:30~2:00 케이스2: “이미 거절된 경우” 표기, 같은 가족의 별도 B snapshot. 합성 거절서→누락 사유→기존 근거 재사용→남은 자료. 케이스1이 실제 거절되었다는 가짜 시간 경과 금지.
2:00~2:15 첫 장면 결과로 복귀: 환자 언어 안내와 영어 의료진용 문서/공유. 승인 성공을 결말로 쓰지 않는다.
2:15~2:38 기술 결정 하나·실제 스택·학생의 실제 기여·AI 도구 보조 범위. 출처 추적/확인/결정적 집계가 어떤 오류를 막는지 화면으로 보여줌.
2:38~2:50 첫 문장 반향: “From a patient's own words to a clear next step for care.” NJ 가족을 위한 설계라는 목적, 합성 사례 표시, 엔드카드.
시간은 리허설 전 편집 예산으로 확약이 아니다. 10초 여유 유지. 외국어 실제 발화와 영어 자막·내레이션은 동시에 길게 겹치지 않게 한다. 타임랩스/로딩 제거는 표시하며 처리시간 수치 주장은 실측만. 첫20초 이해 테스트를 시행하거나 미검증으로 남긴다.
측정: 기본 번역 도구로 준비 vs 앱으로 준비의 소규모 과제 비교. 같은 과제/자료·순서 효과를 고려하고 시간·누락 수·다음 행동 이해를 측정, 표본수 공개. 의료진 평가가 없으면 승인률/진료시간 절감이 입증됐다고 주장하지 않는다.
