# CoverNote Sprint10 — 결과부터 보여주는 데모 개요 v1.3
작성 2026-10-22 America/New_York | 설계 문서, 앱 구현/촬영/공개 미실행

## 하나의 목표와 목소리
환자가 자기 언어로 남긴 경험과 기존 문서를, 의료진이 검토할 자료와 다음 행동으로 연결한다. 두 승인 경로는 이 목표의 적용 상황이다. 제품 가치를 “혁신적”이라는 말로 주입하기보다 매 장면에서 새로 해결되는 문제를 보여준다.
첫인상은 천식 관리/일지/OCR 앱이 아니라 “치료 준비에 필요한 정보가 연결되는 과정”이다. 20초 이후 NJ 천식 사례임을 분명히 하며 질환의 범위를 범용 임상검증으로 확대하지 않는다.

## 오프닝 권장안 — 결과→필요성→방법→시연
실제 합성 환자 결과 화면을 첫 프레임부터 보여준다. 이름/앱명은 짧은 자막, 별도 로고 애니메이션 없음. 작은 PDF 전체나 숫자가 빽빽한 대시보드 대신 ‘자료 연결/미확보/다음 담당자’가 보이는 결과 카드 확대. “일부 자료 연결됨 / 진료팀에 최근 방문기록 요청” 같은 실제 상태를 사용하며 “승인 준비 완료”라고 부풀리지 않는다.

0:00–0:06 내레이션: **“Your experience should not get lost in paperwork.”**
한국어 뜻: “환자의 경험이 서류 속에서 사라져서는 안 됩니다.”
화면은 연결 자료와 원문 출처, 다음 행동을 짧게 보여준다. 합성 사례 배지 유지. 주장 직후 결과를 보여주는 두괄식 시작이다.

0:06–0:20 내레이션 초안: **“We built CoverNote for New Jersey families facing language barriers and difficult treatment approvals. It connects their own words, existing records, and local air data into a clear next step for their care team.”**
한국어 뜻: “언어장벽과 치료 승인 절차에 어려움을 겪는 NJ 가족을 위해 만들었습니다. 자기 언어로 남긴 이야기, 기존 기록, 지역 대기정보를 연결해 의료진과 준비할 다음 행동을 보여줍니다.”
초기 오프닝 총 영어47단어. 실제 발화속도로 리허설해 자막/가독성과 함께 조정한다. 20초를 맞추려고 지나치게 빨리 읽지 않는다. 필요하면 둘째 문장을 “Here is how one family's words become a review-ready summary.”로 줄이고 환경은 다음 구간에 설명한다. review-ready는 의료진 검토용 정리라는 뜻이며 임상 자격/보험승인 완료를 뜻하지 않는다.

0:20 전환: **“Here is how Rosa prepares for her son's next visit.”** — 같은 결과가 만들어지는 과정을 보여준다. Rosa/Diego는 합성이고 학생의 실제 가족/진료 경험으로 사칭하지 않는다.

1:30 두 경우는 같은 가족의 대안 시작 상황이다. 케이스1에서 실제 제출·거절이 즉시 일어난 것처럼 편집하지 않는다. 필요하면 작은 A/B 라벨을 유지한다. 동일 기초기록이므로 환자 소개나 등록을 반복하지 않는다. 영상 중 하나의 질문을 해결한 뒤 다음 질문으로 넘어가며 페이지/메뉴 전체를 순회하지 않는다.

## 계속 볼 이유를 만드는 네 번의 화면 변화
1. **말→기록:** 보호자의 언어가 날짜/증상/불확실한 약 사용으로 나뉜다. 모르는 양은 모름으로 남는다.
2. **기록→맥락:** 기존 사건과 해당 날짜의 지역환경이 연결된다. 환자에게 환경 수치를 입력하라고 하지 않는다.
3. **맥락→요구자료:** 같은 자료가 최초 신청 또는 거절 사유별 준비 항목에 연결된다.
4. **요구자료→행동:** 부족한 자료와 누가 해야 할 일이 명확해지고 의료진용 문서가 나온다.
매번 “새롭다”고 말하는 대신 서로 다른 부담이 줄어드는 사실을 보여준다. 15~25초는 편집상 목표 간격이며 관객 유지 효과가 입증된 숫자가 아니다.

## NJ 연결을 전달하는 방식
지역성은 구체적인 합성 가족·선택 지역·관측일과 출처로 보여준다. 교통 관련 대기/꽃가루/산불·침수 이후 생활환경 같은 지역 배경은 해당 자료가 실제 또는 합성으로 준비된 것만 사용. 메인에서는 대표 환경 사건 하나만 짧게 설명하고 다른 항목은 펼침/부록.
목표 문장: “Designed for New Jersey families whose daily experience, local conditions, and treatment records are rarely organized in one place.” 실제로 다른 시스템에 없다는 보편적 사실로 주장하지 않고 우리가 해결하려는 사용자 과제로 설명한다.
현재 MTA NJ 완화예산이 있으므로 “NJ 피해 완전 배제” 금지. 의원실 자체 원고/현재 소송 진행 여부·통행료가 개인 천식을 악화시켰다는 인과 단정 금지. 정책 논쟁/예산표/소송 상세는 영상의 과제가 아니므로 제출 배경자료에 남긴다. NJ 필요성은 주장할 수 있으나 지역 임상효과/승인 개선은 별도 검증 전 미입증이다.

## 기술과 기능 선택
P0 시연 핵심: 모국어 음성 구조화/확인, 기존 문서 재사용, 환경 자동 연결, 요구-근거 대응, 최초신청/거절 두 상황, 실제 결과/영어 PDF.
P0 반복사용 보완: 홈 위젯 또는 알림 액션 하나. 영상에서 자세히 설명하지 않고 짧게 보여주거나 생략 가능. 영상 생략은 구현 우선순위를 자동 낮추지 않는다.
후순위/중심 시연 제외: 기침·흡입기 음향, 웨어러블, 잔량 카운터 촬영, 지역집계, 금전 보상, 소송 대시보드. 보여줄 수 있다는 이유로 이야기에 추가하지 않는다.

## 기술 설명 초안과 마지막 반향
기술 구간은 실제 구현 후 언어/플랫폼/모델 이름을 넣는다. 확인 전 Flutter/Supabase/온디바이스/서버 구조를 일괄 확정하지 않는다. 기존 앱의 실제 스택을 감사한다.
설명 예: “AI proposes structured events and document matches. We preserve the original source, ask the user to confirm, and use code to calculate dates and summaries.” 실제로 구현한 처리 위치·출처 연결을 화면으로 확인. 학생 구현과 AI 개발 보조를 구분하여 사실대로 설명.
마무리: **“From a patient's own words to a clear next step for care. That is what we are building for New Jersey families.”**
처음의 결과를 다시 보여주는 양괄식. 앱명과 짧은 감사. 승인 획득·의료비 절감·응급실 예방을 입증 없이 결말에 쓰지 않는다.

## 관객 유지·명확성 검수
첫20초만 보여준 제3자에게 ①누구를 위한가 ②무슨 결과가 생기는가 ③왜 NJ에서 만들었는가 질문. 약어/배경 설명 없이 답하는지 실제로 기록. 2분50초 전체 후 ④다음 행동 ⑤일반 번역/일지와 차이 ⑥환경자료가 원인 판정인지 보조 맥락인지 확인. 표본/질문/원응답 보존, 없으면 미검증.
영어 내레이션·스페인어 발화·영어자막이 동시에 경쟁하지 않게 음성 구간에 해설을 멈춘다. 화면당 강조영역 1개, 작은 표는 확대, 자막은 핵심. 긴 로딩/탭 반복은 편집 가능하나 실제 처리시간과 cache는 위장하지 않는다. 이름/앱명/목적/대상/실제 도구/시연 포함 여부를 체크하고 제출규정은 공개 전에 최신 공식 원문으로 재확인.
출처: 사용자가 제공한 “CAC 수상작 데모 시퀀스 레퍼런스.html”의 짧은 문제→실제 흐름→기술적 결정 원칙을 적용. 그 파일은 실제 수상 영상 시청 분석이 아니므로 본 개요의 타이밍/숏 구성도 검증된 수상 공식이라고 부르지 않는다. 실제 경쟁 영상 대비 신선함과 20초 이탈률은 아직 측정되지 않았다.
